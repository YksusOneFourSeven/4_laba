# Инструкция по запуску и ручному тестированию

Эта инструкция предназначена для заполнения [pharmacy-report.md](./pharmacy-report.md). Сам стенд до подготовки инструкции не запускался и тесты автоматически не выполнялись.

## 1. Подготовка

1. Оставьте все семь исходных файлов в одной папке: `index.html`, `practice.html`, `styles.css`, `data.js`, `app.js`, `README.txt`, `report-template.md`.
2. Создайте рядом папку `evidence` для скриншотов и копий выгрузок. Удобные подпапки: `screenshots`, `pair-1`, `pair-2`, `final`.
3. Откройте `index.html` двойным щелчком в актуальном Chrome, Edge или Firefox. Используйте одну вкладку и один профиль браузера.
4. Если браузер показывает предупреждение о невозможности сохранения, не закрывайте вкладку и чаще скачивайте отчёт/журнал. При проблеме с `file://` используйте локальный сервер:

   ```bash
   cd /Users/yksus_147/Downloads/pharmacy-lab
   python3 -m http.server 8000
   ```

   Затем откройте `http://localhost:8000/index.html`. Не меняйте способ запуска посреди работы: у `file://` и HTTP может быть разное хранилище.

5. На экране «Протокол» укажите группу и команду. В отчёте заполните паспорт работы.
6. Сразу запишите браузер и его версию. В Chrome: меню → «Справка» → «О браузере Google Chrome»; в Edge/Firefox путь аналогичен.

## 2. Как фиксировать каждый тест

До выполнения теста откройте соответствующий блок TC в отчёте и прочитайте ожидаемый результат. После выполнения внесите:

1. точную конфигурацию: контур, сборку, API, клиенты витрины/выдачи/поддержки, адаптер;
2. фактический текст сообщения и видимые значения;
3. статус: `Пройден`, `Не пройден`, `Заблокирован` или `Не выполнен`;
4. ID заказа, ключ запроса, сумму, статус и остаток — где применимо;
5. имя скриншота и событие журнала;
6. результат в экран «Протокол» самого стенда, чтобы конфигурация сохранилась автоматически.

Имена скриншотов делайте однозначными: `TC-07-cart-1000.png`, `TC-14-api-v2.png`, `TC-21-after-replay.png`. Не заменяйте скриншотом текстовые шаги и расчёты.

## 3. Рекомендуемый порядок первой пары

1. Переключитесь на рабочий контур.
2. Выполните TC-01. Создайте контрольный заказ `DEMO-001`, проверьте его на трёх рабочих местах, подготовьте к выдаче.
3. На экране «Выпуск» создайте снимок и скачайте `pharmacy-prod-backup.json`. Сразу скопируйте его в отдельное безопасное место.
4. Скачайте текущие `pharmacy-session.json` и отчёт.
5. Переключитесь на тестовый контур и выполните TC-02–TC-10. Между независимыми граничными сценариями очищайте корзину; перед проверкой исходных остатков нажимайте «Сбросить данные тестового контура».
6. Для TC-11–TC-14 меняйте сначала клиент только одного рабочего места, остальные держите совместимыми. Перед сменой конфигурации запишите ID и сумму сохранённого заказа.
7. Если результат отличается от ожидания, сохраните тест со статусом `Не пройден`, затем создайте карточку дефекта с минимальными шагами. Не регистрируйте дефект только по чтению исходного кода.
8. Заполните промежуточное решение по 1.5.0-rc, скачайте отчёт и журнал.

## 4. Как выполнить проверки промокода

Каждый сценарий начинайте с пустой корзины:

| TC | Корзина | Ожидаемая сумма | Скидка | Итог |
|---|---|---:|---:|---:|
| TC-06 | 3 Аква + 2 Бинта | 990,00 ₽ | 0,00 ₽ | 990,00 ₽ |
| TC-07 | 4 Аква | 1 000,00 ₽ | 100,00 ₽ | 900,00 ₽ |
| TC-08 | 4 Аква + 1 Пакет | 1 010,00 ₽ | 101,00 ₽ | 909,00 ₽ |
| TC-18 | 5 Салфеток + 1 Пакет | 1 009,95 ₽ | 101,00 ₽ | 908,95 ₽ |

Количество меняйте прямо в корзине. После ввода `DEMO10` нажмите «Применить». Снимайте экран так, чтобы одновременно были видны сумма товаров, скидка и итог.

## 5. Как проверить совместимость

На экране «Выпуск» в тестовом контуре последовательно задайте:

1. API v1 + проверяемый клиент v1 + адаптер выкл. — TC-11;
2. API v1 + проверяемый клиент v2 + адаптер выкл. — TC-12;
3. API v2 + проверяемый клиент v1 + адаптер выкл. — TC-13;
4. API v2 + проверяемый клиент v1 + адаптер вкл. — часть TC-14;
5. API v2 + витрина v2 + выдача v1 + поддержка v1 + адаптер вкл. — полный TC-14.

Для каждого случая откройте нужное рабочее место, запишите наличие/отсутствие `SCHEMA_MISMATCH`, раскройте «Ответ API» и сохраните поля контракта. После несовместимой конфигурации верните совместимую и убедитесь, что ранее сохранённый ID снова виден — это отдельное доказательство сохранности данных.

## 6. Вторая пара

1. В тестовом контуре выберите 1.5.1 и совместимую смешанную конфигурацию.
2. Сбросьте только тестовые данные перед граничными тестами.
3. Выполните TC-15-R, TC-16-R, TC-17-R с теми же данными, что исходные тесты. Укажите связь с исходным TC и дефектом.
4. Выполните регрессию TC-18 целиком.
5. Перед выпуском сравните контрольный заказ TC-01 со снимком. Если создаёте новый снимок, не перезаписывайте старый: сохраните оба с датой в имени.
6. Выполните TC-19. После выпуска создайте рабочий заказ с кодом `DEMO-002` и явно пометьте его как созданный после снимка.
7. Скачайте промежуточные отчёт и журнал.

## 7. Инциденты

Все инциденты выполняйте в тестовом контуре. Перед каждым очистите корзину и начните новую попытку.

### INC-1 / TC-20

1. Соберите корзину.
2. На «Выпуске» установите «Нет ответа до записи».
3. Оформите заказ один раз.
4. До повтора откройте «Мои заказы» и «Журнал», запишите ключ, число заказов и остаток.
5. Не меняя корзину и точку, повторите оформление.
6. Запишите итоговое число заказов и события журнала.

### INC-2 / TC-21

1. Соберите новую корзину.
2. Установите «Нет ответа после записи».
3. Оформите один раз.
4. До повтора зафиксируйте созданный ID, ключ, число заказов и остаток.
5. Вернитесь к оформлению без изменения корзины или точки и повторите.
6. Убедитесь по фактам, был ли дубль и было ли повторное списание.
7. В «Поддержке» создайте заявку по фактическим данным этого сценария.

### INC-3 / TC-22

1. Соберите новую корзину.
2. В панели изменения остатка установите остаток этого товара в выбранной точке равным 0.
3. Попробуйте оформить и зафиксируйте сообщение, число заказов и остаток.

## 8. Откат и восстановление

1. До любых действий скачайте финальные на этот момент отчёт и журнал.
2. Запишите количество, все ID, суммы, статусы и остатки рабочего контура.
3. Нажмите «Вернуть предыдущую конфигурацию» и повторно сравните те же данные на трёх рабочих местах.
4. Только после фиксации отката нажмите «Восстановить данные из снимка».
5. Снова запишите количество и ID. Не пытайтесь вручную «исправить» исчезновение заказа после снимка: это ожидаемый предмет измерения.
6. Для интервала потери возьмите время создания снимка из `pharmacy-prod-backup.json` и время последнего отсутствующего `ORDER_COMMITTED` из `pharmacy-session.json`. Вычислите разницу и внесите её в TC-23.

## 9. Что прислать для заполнения отчёта

После первой части пришлите:

- заполненные факты TC-01–TC-14 или экспортированный отчёт стенда;
- `pharmacy-session.json`;
- `pharmacy-prod-backup.json`;
- карточки/описания обнаруженных дефектов;
- скриншоты с именами по TC, если они есть.

После второй части дополнительно пришлите результаты TC-15-R–TC-23, заявку поддержки и финальные выгрузки. По этим данным можно заполнить макет без выдумывания результатов.

## 10. Финальная самопроверка

- не менее 14 реально выполненных результатов;
- есть границы 990/1000/1010 и дробное округление;
- есть все четыре случая совместимости и смешанная конфигурация;
- есть повторные тесты 1.5.1 и регрессия;
- есть контрольный заказ до выпуска и новый заказ после снимка;
- есть INC-1, INC-2, INC-3 и заявка поддержки;
- показана разница отката конфигурации и восстановления снимка;
- итоговое решение ссылается на конкретные TC и доказательства;
- приложены оба JSON-файла и исходные файлы проекта.
